# CP-07 — thin Pi commands

## Boundary and acceptance

CP-07 advances the BUILD_PLAN command-parity/no-background-process gate and the F-02/F-03/F-04/F-08 and P-03/P-04 behaviors it exposes. It does not independently certify those product-wide conditions, CP-08, deployment or whole V1 completion.

`extensions/factory.ts` only registers `/factory`. It frames quoted arguments, allows `status`, `validate`, or `context`, then awaits the proven CLI as one `node:child_process` spawn (argument array, `shell: false`, stdin ignored) of the Pi host's Node interpreter with the session cwd and the package's built `dist/src/cli.js`. Pi's `exec` helper is deliberately not used: in 0.99.2 it reports a signal-terminated child as code 0 and decodes each pipe chunk separately, corrupting multi-byte UTF-8 split across chunks. There are no lifecycle subscriptions, worker launches, state database, scheduling, home inference, model requests or shipping controls. Registration and reload launch nothing. CLI scope/freshness/budgets/no-secret and CP-06 guards remain in their existing owners.

The wrapper leaves supported-command option validation to the CLI, including its existing permissive global-option parsing. It never changes or adds CLI behavior. Empty/unsupported command, NUL and unterminated quoting are wrapper errors (`FACTORY_ARGUMENT_ERROR`, exit 2). Missing/extra/unknown CLI arguments, unavailable integrations, stale evidence and invalid contracts retain exact CLI stdout, stderr and exit code. Quoting is argv framing only; single quotes preserve literal Windows/UNC backslashes. No shell expansion occurs.

Pi slash handlers return `Promise<void>`, not an OS exit code. The displayed `factory-result` includes stdout/stderr plus an `exit: N` label (suffixed ` (signal NAME)` on signal termination); `details` is exactly `{ stdout, stderr, exit_code, signal, killed }`. Streams are collected as bytes and decoded once after the process closes, so they are unmodified UTF-8 regardless of size. A signal-terminated CLI reports `exit_code` 128 + signal number, the signal name and `killed: true`; otherwise `signal` is null and `killed` false. Wrapper-side failures put a single diagnostic in `stderr` with empty `stdout`: `FACTORY_ARGUMENT_ERROR` (exit 2) for framing/unsupported commands, and `FACTORY_RUNTIME_UNAVAILABLE` (exit 3) when the CLI cannot be started (for example a missing session cwd) or the Pi host is not a Node interpreter.

The CLI is started only when `process.execPath` is a Node interpreter: not a Bun runtime (`process.versions.bun`), not a Node single-executable application, and an executable named `node`/`nodejs` (optionally versioned, optional `.exe`). Installed Pi also ships Bun-compiled and bundled-Node release binaries (e.g. the `pi.dev` installer) whose `execPath` is Pi itself; spawning that with the CLI path would start a nested Pi prompt. Those hosts fail closed with `FACTORY_RUNTIME_UNAVAILABLE` and start no process; use the CLI directly. Only npm-installed Pi on Node is proven. Pi's process exit and RPC prompt acceptance cannot be interpreted as CLI success. Use the CLI directly for OS-status/one-object JSON consumers. Command output is a normal Pi message, not a new Factory task-state store. It triggers no model turn.

## Executable proof

Build first. Normal commands and proofs below make no model request or login. Installations can use the network; normal Factory operation is offline. Use only disposable DUMMY fixtures.

```sh
npm ci
npm run build
npm run format:check
npm run lint
npm run typecheck
npm test

# Actual current installed Pi package discovery, prompt-command dispatch,
# exact CLI stdout/stderr/exit parity and SDK runtime replacement:
CP07_PI_PACKAGE_ROOT=/absolute/installed/pi-coding-agent \
  PI_OFFLINE=1 npm run proof:cp07:pi

# Additionally initialize only two normative fixture originals, index with
# the already verified offline model, and exercise context success/budgets/stale:
CP07_PI_PACKAGE_ROOT=/absolute/installed/pi-coding-agent \
  CP07_REAL_CTX=1 PI_OFFLINE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  npm run proof:cp07:pi

# Actual installed CLI/TUI package load and built-in /reload (Linux PTY):
npm run proof:cp07:reload -- --pi-bin /absolute/path/to/pi \
  --output .factory/state/cp07-evidence/reload
```

`test/cp07-extension.test.mjs` was written first: before the extension existed, its executable import/behavior tests failed (exit 1). It covers missing/unsupported command, malformed quoting/NUL, CLI argument delegation, spaces, metacharacters, literal Windows paths, large untruncated output, nonzero statuses and no process at registration. Review round 1 replaced its mocked `exec` with real DUMMY CLI subprocesses and added tests for multi-byte UTF-8 split across pipe chunks, SIGKILL termination (exit 137, `signal: "SIGKILL"`), unavailable cwd, and Bun/single-executable/non-`node` hosts (a DUMMY `pi` executable is never invoked). With Pi 0.99.2's `execCommand` substituted, the UTF-8 test failed (U+FFFD) and the signal test failed (`exit_code: 0`); both pass with the direct spawn. The actual installed-Pi smoke was also written/run before implementation: package command discovery failed (exit 1, zero registered extensions), not counted as passing proof.

`test/cp07-pi-smoke.test.mjs` always executes the pinned real development SDK (or explicitly selected installed SDK), resource loader and `session.prompt()`; it is not mocked command callbacks. It checks local package/skill discovery, missing/extra/unknown-argument failures, invalid contracts, absent integration/home, human/JSON validate/status parity, replacement registration on `session.reload()`, no agent turn/network, and on Linux no residual children after load/each CLI return/reload. The optional real CTX mode adds exact human and warmed JSON context parity, HYBRID_SEMANTIC scope/budget checks, insufficient-budget and stale-original failures. The prior receipt is deliberately warmed before comparing JSON context outputs; receipt timestamps are not altered or hidden.

`scripts/cp07-pi-reload.py` launches only an identified disposable installed-Pi TUI in a sterile credential-free HOME, explicit offline mode and package path. It waits for package startup, then executes validate, unsupported run, missing context ID, built-in `/reload`, then `validate --json`, `status` and a status with a random `POSTRELOAD_DUMMY_*` extra argument, finally `/quit` and observes exit 0. Each step's marker must be absent from all earlier terminal output, so a post-reload result cannot be satisfied by a transcript redraw, and every CLI step must display the expected `exit: N` label after its marker (0, 2, 2, then 0, 0, 2). `reload.json` records each command, marker and observed `cli_exit_code`. This tests the real CLI input path, not a mocked `reload` callback. A failure retains its DUMMY-only terminal log and is not passed. It does not drive Herdr lifecycle.
