## Read-only Pi authentication correction

The original PR10 CLI worker is superseded by a bounded Pi 0.85.1 public-SDK path. `scripts/replay-cp06-worker.mjs` now runs a DUMMY-only gate before opening any configured credential path or making a provider request. That gate proves the retained-capability counterexample, then proves the actual evaluated child has empty capability sets, locked root securebits, `no_new_privs`, and inherited seccomp denial of remount/unmount, alternate mount APIs, namespace creation/entry, handle-based inode reopening, UID change, ptrace/process-memory access, and child-process variants. Source and target are distinct `ro,nosuid,nodev,noexec` mount instances of one pinned `O_NOFOLLOW` regular inode. Their containing source and target directories are separate read-only bind mounts inside the private namespace, while the DUMMY proof root used as scratch remains writable. The host namespace and host parent permissions are unchanged. Proof support is limited to Linux x86-64 and WSL2 Linux guests with the same required kernel namespace, mount, seccomp, and capability behavior; unsupported Linux x86-64 or WSL2 environments, libseccomp, helper compilation, Pi version, or a cleanup failure block the proof with no unsandboxed fallback. WSL2 coverage is only for the Linux guest proof environment, not Windows host credential or filesystem semantics. Windows and macOS are not claimed.

The evaluated worker injects `Cp06ReadOnlyCredentialStore` into `ModelRuntime.create({ refreshOnCreate:false, allowModelNetwork:false, modelsPath:null })` and passes that runtime to `createAgentSession` with an in-memory session, an empty resource loader, and one SDK `read` tool wrapped by a pre-execution canonical-path and range allowlist. The wrapper rejects every path except the already-canonical exact original, including credential paths, arbitrary project paths, and symlink aliases, before Pi's SDK read implementation can consume the immutable pinned snapshot. `modify` and `delete` reject before any callback or persistence. Expired and near-expiry DUMMY OAuth cases record zero refresh callbacks, zero `toAuth`, and zero persistence; an unexpired offline case resolves through `toAuth` with zero refresh/network/mutation. The live worker preflights enough validity for its timeout plus Pi's five-minute window and records only compact event/transcript and non-credential source hashes, counts, and parsed output, never credential contents or raw events. Real credential source integrity uses pinned device, inode, link, mode, size, and timestamp metadata plus mount identity; credential bytes are never hashed. Byte hashes in the isolation adversary are literal DUMMY-only controls.

The current global Pi may be newer than the proven interface. Validation therefore installs exact Pi `0.85.1` under ignored task-local `.factory/state/cp06-sdk/` and supplies that installation's canonical package root and bin path explicitly. Both paths must equal the expected task-local locations, the bin symlink must resolve into that package, and its package metadata, declared entry, executable version, and complete published file manifests must agree with the independently pinned exact-version npm artifacts in `.factory/cp06-sdk-integrity.json`; inherited `PATH`, a global installation, an unrelated same-version package, and same-version file substitutions are rejected before SDK import without fallback. The pin records npm tarball SHA-512 SRI and sorted `[relative path, file SHA-256]` manifest SHA-256 and file count for both packages; it excludes nested installed `node_modules` from each package manifest, while separately verifying the resolved `pi-ai` package. It does not attest the registry itself, transitive packages other than `pi-ai`, or immutable files after this check. The global installation/configuration remains unchanged. The DUMMY provider resolver uses the selected package's ESM dependency context and the dependency's supported `import` export; it rejects a non-`0.85.1` `pi-ai`, a dependency outside the selected installation, or absent import resolution. Evidence records the selected Pi and resolved dependency package/entry paths, trusted artifact pins, manifest digests, and SHA-256 entry digests. To reproduce a pin independently, download the named exact-version tarballs into ignored `.factory/state/`, compare each tarball's SHA-512 against the tracked SRI, extract into a disposable directory, sort all regular published files by relative path and compute SHA-256 of JSON-serialized `[path, SHA-256(file)]` pairs (with no extra files or symlinks); compare count and digest to the tracked pin. Never derive a new trusted pin from the selected installation under evaluation. This resolver requires Pi's own Node floor (22.19 or newer) and Node's `--experimental-import-meta-resolve` support; inability to use it blocks rather than selecting a global fallback.

Run the standalone DUMMY gate with `npm run proof:cp06:auth-security`. A positive real semantic replay remains `npm run proof:cp06:worker`, but it is attempted only after that DUMMY gate and fail-closed preflight pass. No destructive operation is ever directed at the real credential source or mounted target.

## Normative result

The PR #8 measurement is a **failure**, not a P-06 pass. Its predeclared oracle
counted 15 of 24 topical excerpts as irrelevant, every one of 10 packs had at
least one irrelevant excerpt, and AUTH was missing from one pack. Bounded bytes
do not make irrelevant authority relevant. The original figures remain in the
runtime evidence manifest and Git history; this correction does not relabel or
hide them.

Independent exact-head review then rejected PR #9 for three additional concrete
cases: empty task-local selection widened to the CTX corpus, the worker oracle
accepted unsuccessful or partial reads, and the critical fixture disclosed a
foreign identifier during creation. The final correction adds executable
regressions for those cases without expanding CP-06's architecture.

The smallest in-scope correction uses CTX's existing repeated `--document`
filter. Factory passes the task's reviewed `context.required` paths to `ctx
pack`; when that valid selection is empty, it passes the mandatory project
`documents.required` paths rather than accidentally issuing an unrestricted
query. Those same originals are still read exactly and included with their
digests. This is source selection before retrieval, not post-retrieval deletion:
raw CTX output remains in ignored proof scratch, provenance is unchanged, and a
missing declared source still fails closed. No CTX code, parallel retrieval
system, model router, supervisor, CP-07 extension, or CP-08 application was
added.

The contract policy now makes `context.required` the narrow task-local authority
selection. Known sources that can decide an acceptance or risk condition belong
there. A worker that discovers an omission performs one targeted exact-original
read, records the corrected assumption, and adds only that durable source before
regeneration. Global constraints and exact required originals remain visible.

`offline_ready=true` and `network_attempted=false`; status must be clean
`HYBRID_SEMANTIC` with the semantic channel active. The runner aborts otherwise.
It indexes only the fixture's deliberate authoritative Markdown.

The bad-path control invokes real CTX with the AUTH query before `docs/AUTH.md`
is indexed and without a document selection. On the recorded replay it exited
0, omitted AUTH, and returned unrelated topical `docs/DELETION.md` and
`docs/OBSERVABILITY.md`. The raw response is retained in ignored scratch. This
corroborates the user-visible PR #8 problem rather than treating small byte size

The one-condition counterfactual keeps every AUTH task field fixed except
`context.required`:

```text

after:  [PROJECT.md, ARCHITECTURE.md, docs/AUTH.md]
```

Before correction, the bounded pack omits the decisive original. After the one

principal-derived ownership, ignored request ownership, `401` for missing or
forged credentials, and non-disclosing/non-mutating `404` for cross-account

The fixed sample is ten bounded packs: two bounded-risk, six normal-risk, and

## Fresh-context targeted-original correction

After deterministic checks and the real-CTX replay, a new Pi `0.85.1` SDK
session runs with an injected read-only credential store and model runtime, an
in-memory session/settings manager, an explicit resource loader containing no
extensions, skills, prompts, context files, or themes, and exactly one guarded
SDK `read` tool. Its initial handoff contains exactly the AUTH-before contract,
bounded missing-AUTH pack, and a short deterministic evidence statement—no
prior transcript.

The fresh-worker handoff deliberately omits the concrete rule that
request-supplied owner fields are ignored at creation time while retaining the
already observed `401` and concealed, non-mutating `404` evidence. The worker
reports `MISSING_SOURCE`, performs exactly one read of the supplied
`docs/AUTH.md` original, performs no broad scan, recovers principal-derived
creation ownership and the ignored request-owner rule, and identifies the
missing creation-time integration evidence.

The exact original is opened with `O_NOFOLLOW`, identity-checked, and snapshotted
before provider execution. At the actual tool boundary, the lexical path and
range are checked and the named path must still identify the pinned regular
file; Pi's SDK read implementation receives only the immutable snapshot, so a
replacement race cannot redirect the provider-visible bytes. The audit
correlates `tool_execution_start` and `tool_execution_end` by tool-call ID and
event order, requires `isError: false`, and forbids all other start or
completion events. An omitted range is accepted; the SDK's explicit first-line
form is accepted only as `offset: 1` with a positive integer `limit`, and only
when the returned UTF-8 bytes and SHA-256 still equal the complete tracked exact
original. Offset-only, limit-only, wrong-start, and partial results fail. The
final response must follow the successful completion. Deterministic protocol
tests reject omitted, failed, partial, mismatched, out-of-order,
malformed-orphan, extra-project, credential-path, symlink-alias, and
post-construction replacement-race cases.

The genuine Pi SDK process runs in a private Linux user/mount namespace only
after the complete DUMMY auth and OS preflight passes. A supervisor pins the
regular source inode with `O_NOFOLLOW`, creates distinct source/target bind
mounts with read-only VFS flags, and closes the pin before launch. The evaluated
child has all capability sets empty, locked securebits, `no_new_privs`, and an
inherited seccomp filter blocking mount and namespace escapes, alternate inode
handles, ptrace/process-memory access, and namespace-bearing child calls. Its
credential store rejects refresh/mutation callbacks before entry; expired or
near-expiry OAuth is therefore blocked before a provider request or persistence.
A missing credential source is a sanitized `CP06_CREDENTIAL_SOURCE_MISSING`
missing-source result with exit 70, not an unsupported-isolation result; a
simultaneous cleanup failure retains both typed causes. Other setup,
helper/version, auth-validity, timeout, audit, and cleanup failures are reported
as blocked/nonzero with no unsandboxed fallback. The evaluation state
is removed and no raw transcript is retained. Native Windows/macOS isolation is
unsupported rather than claimed. Model wording is nondeterministic; the
protocol, exact bytes, and isolation assertions are not.

## PR11 A1/C1 correction and proof boundary

The independent review of PR11 at `33b2724e3316272aac1c563086d2ce5e77d496ca`
reproduced two additional failures: a local faux SDK response with
`evidence_gaps: []` was accepted, and an expired-auth exit skipped the outer
runner's `finally`, leaving its evaluation directory and empty mount placeholder.
Neither finding demonstrated credential mutation; the DUMMY S1/S2 controls passed.

The worker now requires an exact top-level response shape with one declared
canonical read, two fixed corrected-constraint values, no secondary evidence channel,
and an executable structured creation-evidence disposition:

```json
{
  "evidence_gaps": [
    {
      "id": "creation-time-ownership",
      "status": "unverified",
      "missing_checks": ["principal-derived-owner", "request-owner-ignored"]
    }
  ]
}
```

The check order inside `missing_checks` is immaterial, but the two
`corrected_constraints` values are fixed canonical strings in fixed order so
that field cannot carry an additional free-text evidence disposition. Missing,
empty, duplicate, wrong, or contradictory dispositions fail; recovering a
requirement by reading its original is not a passing behavior test. Extra fields
or prose in this gap are rejected rather than interpreted as an alternate
verification channel. The existing exact-original read and source-scope oracle
remain mandatory.

`npm run proof:cp06:auth-security` additionally runs the actual SDK worker with a
local faux provider in the inherited capability-free/seccomp context. It records
a valid structured positive, missing/empty/contradictory gap negatives, expired
and near-expiry preflight denial, and an SDK timeout. Every case is explicitly
`fixture_origin: true`, `semantic_acceptance: false`; these are protocol and
infrastructure proofs, never live-model acceptance. Default AuthStorage, refresh,
and network entry are instrumented and must remain zero. The full read still
uses Pi's actual SDK read implementation behind the pre-execution allowlist,
not a fabricated completion event.

The runner and namespace supervisor await cleanup before setting an exit code.
When execution and cleanup both fail, the cleanup error retains the primary
cause and its exit identity. Supervisor output is an allowlisted stage/code/
description protocol; launch, timeout, child exit, source-integrity audit,
output audit, and cleanup causes remain distinct without retaining child stderr
or arbitrary exception payloads. PR12 still parsed successful-child output after
cleanup, so malformed output plus cleanup failure lost the parse/audit cause.
The correction keeps child status, source-integrity verification, compact JSON
parsing, and evidence assembly inside the cleanup action. The shipped
actual-boundary regression separately triggers successful-child malformed
output and an independent awaited cleanup error, then verifies that the
supervisor JSON, namespace wrapper, and replay `blocked.json` retain both cause
identities; child-exit+cleanup, cleanup-only, audit-only, and success remain
separate controls. `npm run proof:cp06:worker-cleanup` executes the full runner
with task-local expired/near-expiry DUMMY auth and missing-source setup, asserts
the blocked result, unchanged DUMMY source, absence of a pass manifest, and
removal of the evaluation home. Unit tests also inject setup, launch, timeout,
audit and cleanup failures at the executable supervisor boundary; they are
distinct from actual kernel/SDK proof. No real credential read, mount, refresh
or model request is needed for these regressions.

The strict-agent CTX audit is a separate qualification. PR11's ordinary Factory
STANDARD/HYBRID_SEMANTIC sample passed 10/10 with zero irrelevant provenance;
replaying those selections with `--strict-agent --require-semantic` reported ten
PARTIAL results because strict cross-document discovery required filtered-out
normative entries. This is not strict COMPLETE evidence. Do not widen filters,
hide omissions, or label the DUMMY worker as semantic acceptance to cure it.
Final-head manifests must be regenerated after committing the correction. The
fresh-worker gate is verified only by a successful final-head real model/SDK
manifest produced after the DUMMY gate through the hardened read-only path; a
fixture-origin stream or an earlier SHA cannot substitute. Independent
acceptance remains separate, and the prior PR11 report is not approval of this
head.

## Acceptance and residual limitations

P-06's STANDARD ten-pack subgate passes when the corrected, predeclared sample
is replayed successfully; it does not substitute for the final-head real
fresh-worker manifest or independent CP-06 review. The original PR #8 sample
remains explicitly failed. P-07 passes because the structured finding,
fail-before, repair, final behavior retest, and auth retest are executable and
bound to the replayed SHA. CP-06 makes no change to Firstmate dispatch, delivery,
or no-mistakes policy.

Residual limits are explicit: this is a small Linux fixture using CTX `1.0.0`,
not a universal retrieval-quality claim; native Windows/macOS replay is
unverified; semantic model wording and ranking can vary in later CTX/model
versions and therefore fail the proof rather than being silently accepted; and
raw runtime artifacts remain intentionally ignored and must be regenerated by
an independent reviewer.
